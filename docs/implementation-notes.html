🔑 Quyết định quan trọng

1. Đặt CDN module ở core/cdn/ thay vì services/

Spec gợi ý app/core/cdn/. Codebase hiện tại không có thư mục core/, nhưng quyết định tạo mới vì đây là infrastructure-level code (không phải feature service). Tách biệt khỏi services/ giúp rõ ràng ranh giới: services/ cho business logic, core/ cho infrastructure.

2. Dev environment vẫn trỏ Worker đã deploy

wrangler dev không hỗ trợ cf.image (Cloudflare Image Resizing chỉ hoạt động ở edge production). Quyết định: dev environment cũng dùng URL Worker đã deploy (https://image-resize.d-c-thanh1997.workers.dev). Cần có internet khi dev, nhưng tránh confusion khi ảnh không resize được trong wrangler dev.

3. Đổi tên url → storagePath trong model và Input

Backend thực tế trả về field storagePath (R2 path), không phải URL đầy đủ. Model cũ dùng url là sai về semantic. Quyết định đổi tên để nhất quán với backend và tránh nhầm lẫn giữa CDN URL (build bởi frontend) và storage path (từ backend).

4. ImagePreview.file trở thành optional

Trước đây file luôn required, nhưng ảnh từ server không có File object — chỉ có storagePath. Đổi thành file?: File và storagePath?: string. Ảnh mới upload có file; ảnh từ server có storagePath. Dùng previewUrl làm trường chung cho template.

5. Tối ưu Responsive Images bằng `srcset` và `sizes`

Để Grid image-upload hiển thị tối ưu trên nhiều kích cỡ màn hình, chúng ta chuyển sang dùng srcset kết hợp sizes đối với ảnh lấy từ CDN thay vì hardcode width=800.
Các mốc srcset: [200, 400, 600, 800].
Giá trị sizes: (max-width: 767px) 50vw, (min-width: 768px) 300px, 100vw (dựa theo layout CSS Grid của preview items).
Đối với ảnh mới chọn ở local (chưa lưu R2), ta vẫn hiển thị thông qua Blob URL gốc để giảm thiểu latency xử lý ở client.

⚖️ Tradeoffs

Bỏ logic fetch(url) trong imageUrls setter

Trước: Component fetch blob từ URL về client để tạo File object → tốn bandwidth, chậm, và tạo File để làm gì?
Sau: Ảnh từ server hiển thị thẳng qua CDN URL resize (width=800, quality=85). Chỉ fetch/create File khi user chọn ảnh mới từ local.
Mất gì: Không còn File object cho ảnh cũ → không thể re-upload ảnh cũ như một "new file". Nhưng không cần thiết vì ảnh cũ đã có id → gửi fileIds lên server là đủ.

Blob URL vs Data URL cho ảnh mới

Trước: Dùng FileReader.readAsDataURL() → Data URL (base64) lưu trong memory cho cả vòng đời component.
Sau: Dùng URL.createObjectURL() → Blob URL nhẹ hơn nhiều, và được revokeObjectURL() khi remove/clear để tránh memory leak.
Bonus: Không cần async callback (FileReader.onload) nữa → logic đơn giản hơn, không cần đếm index để emit.

Params sorted trong buildQuery()

Gọi params.sort() trước khi stringify để đảm bảo query string luôn có thứ tự cố định (ví dụ: ?quality=75&width=300). Điều này giúp CDN cache hit rate cao hơn vì cùng tham số nhưng thứ tự khác nhau sẽ được normalize về cùng 1 key.

⚠️ Lưu ý khi deploy

Breaking change: Nếu backend vẫn đang trả về field tên url trong response của GET /bills/:code, cần backend đổi tên thành storagePath (hoặc thêm alias). Frontend đã cập nhật TypeScript type để expect storagePath.
Breaking change: Bất kỳ component nào khác dùng [imageUrls] binding của ImageUploadComponent cần đổi sang [imageStoragePaths] và truyền { id?, storagePath }[] thay vì { id?, url }[].
